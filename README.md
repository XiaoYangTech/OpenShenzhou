# OpenShenzhou（开放神州）—— 开源的微软自然语音推理引擎本地复现

> **📌 本项目是「亿方听力大师」（ListextEditor）的附属项目。**
> 如果想快速体验本项目效果，或直接制作听力材料，推荐使用 **亿方听力大师** —— 全网最好用的听力材料制作工具，**完全免费**。


> **一句话**：把 Windows 自带的高质量神经语音引擎（讲述人自然语音 / Azure 嵌入式语音同源）**在本地、离线、跨平台**复现出来——不调用微软引擎、不联网、不需要 SAPI 注册，只用 ONNX Runtime 加载你自己解包的语音包模型，合成结果与官方引擎**逐采样一致**（int16 残差 ≤1 LSB）。

## 这个项目是干什么的

Windows 上有一套音质接近真人的本地神经语音引擎，但它只能在 Windows 里通过系统接口使用：推理代码是闭源 DLL、模型是加密容器、要注册 SAPI 适配器，Python/Node 程序、Linux 服务器和容器都用不了。

**OpenShenzhou 的目标是做一个"开源替身"**：在任意平台用纯 ONNX Runtime 复现它的推理与文本前端，并且用可验证的指标证明结果一致——不是"听起来像"，而是：

- **模型层**：给定相同音素序列，合成音频与官方引擎**逐采样一致**（int16 残差 ≤1 LSB，99.7%+ 采样完全相同）；
- **前端层**：文本→音素 id 的转换与官方引擎**逐 id 一致**；
- **双端**：Python SDK 与 Node SDK 输出**完全一致**。

为此，本项目通过黑盒逆向 + "把引擎当标注器"的探针方法，复刻了：加密模型的解密与明文 ONNX 还原、8 个私有流式算子、分块调度/缓存/量化、中文 LSTM 断词模型与词界后处理、多音字 CRF 读音模型、多语种词表与连诵/省音等前端规则。

## 原版是怎么运行的（SAPI 链路）

原版在 Windows 上的调用链是：

```
应用程序（SAPI.SpVoice / System.Speech / WinRT）
  → SAPI5 运行时 sapi.dll（框架：根据"语音令牌"找引擎、传文本、收音频）
  → 语音令牌（注册表 ...\Speech\Voices\Tokens\...，含 Name/Language/CLSID）
  → NaturalVoiceSAPIAdapter（开源社区转接器，注册成 SAPI 引擎；每个语音包一个"系统音色"）
  → Microsoft.CognitiveServices.Speech.extension.embedded.tts.dll（真正干活：解密模型 → ONNX Runtime）
  → 24 kHz PCM 音频
```

几个关键事实：

- **SAPI 只是"插座"**，不负责合成；真正合成声音的是嵌入式语音 SDK（`embedded.tts.dll`）；
- 转接器需要 `regsvr32` 注册 COM、把语音包路径写进注册表，SAPI 才能看到这些音色；
- SAPI 的语速（Rate）是框架在**模型外**做时间伸缩，不是模型内部参数；
- 本项目开发期的"探针服务器"直接调用嵌入式 SDK（绕过 SAPI）来采集标准答案，仅用于研究，不在 SDK 中。

**我们的 SDK 直接替换了这条链路的后半段**：不注册 SAPI、不走 `sapi.dll`、不依赖 Windows 引擎，纯 ONNX Runtime 执行同一份语音包模型，输出与官方引擎逐采样一致（int16 残差 ≤1 LSB）。

## SDK 能做什么

Python SDK 与 Node SDK（分别见 `python` / `node` 分支）均支持：

| 能力 | 说明 |
|---|---|
| **同时加载多个语音包** | 一个进程里 new 多个 `TTS(语音包目录)` 实例即可（每个实例独立模型/状态）；本机 23 个音色包可任意组合 |
| **指定发音人** | 每个语音包目录对应一个发音人（如 `Xiaoxiao_Female_zh-CN`、`Aria_Female_en-US`），传哪个目录就用哪个 |
| **设置语速** | `speak(text, out, speed=1.0)`；speed 是模型内 `speed_ratios` 调节（0.7/1.0/1.3 实测时长 5.08s/3.48s/2.71s） |
| **Node SDK 音频保真度** | Node 分支文本前端（ids/词表）与 Python 完全一致（中英 1682+899 句逐 id）。Node decoder 按语言选择近似策略：英文等按**引擎同款分块调度**执行（首块 64、中间 64/32、末块 flush，LSTM 状态跨块携带），自然音频与引擎 corr≈0.9988、变速率端到端 corr≈0.9994（长度差 ≤ 数采样）；中文/韩文因 JS 未含引擎流式卷积缓存，改用**整段解码**更接近引擎（实测中文 5 句 0.978~0.996、韩文 3 句 0.954~0.994，仍低于 Python 的逐采样一致）。逐采样精确复刻以 Python 分支为准。逐采样精确复刻以 Python 分支为准（引擎的流式卷积/延迟对齐算子完整复刻，corr=1.0、残差 ≤1 LSB） |
| **词边界事件** | Python SDK `word_events()` 复刻官方 WordBoundary 事件（`audio_ticks`/`text_offset`/`text_length`/`word`/`type`），英文 19/19 案例逐字段一致 |
| **多句/标点** | 多句逐句合成（与引擎逐采样一致）、省略号/引号/数字/日期/时间等标点结构已对齐 |
| **无 SAPI 依赖** | 无需注册 COM/注册表，不调用 Windows 引擎；Windows/Linux/macOS 通用 |
| **无服务器** | SDK 只是本地库 + CLI，不含 HTTP 服务；历史开发用探针服务器未进入仓库 |

## 已知差异与限制

| 项目 | 现状 |
|---|---|
| **SSML 韵律** | Python SDK 已支持 `<speak>` / `<prosody volume|rate|pitch>` / `<break>`：`volume` 已完全复刻（引擎在 core 侧对最终 int16 PCM 做**定点乘 `floor(x*K/32768)`**，K 为实测的 101 级增益表；实测 volume 20/50/80/90 长度精确、99% 采样相同；volume+rate 组合 eq 99.82%、maxdiff 1）；`rate` 已确认由**音频域基音同步拼接**实现，SDK 用引擎同款算法复刻：总因子 f20 = float32(1+float32(pct)×float32(0.01))（RateAdjustment=100 时）或 float32(float32(RateAdjustment×pf)×float32(0.01))，Aria/Katja 16 组实测 f20 **逐位相等**，Alvaro(95)/Conrad(110)/Keita(90) 端到端长度精确、corr=1.0（见 §5.8）；官方 SAPI 路径实测（24kHz）：算法对引擎输入流**逐采样一致（maxdiff=0）**，SDK 端到端 99.4%~99.7% 采样相同、残差 ≤1 LSB（见 §5.8）；`pitch` 已确认与 `rate` 共用同一音频处理器并**逐采样精确复刻**（rate+pitch 同时出现时走同一处理器一次完成：PSOLA(r=f20/f28)→定点重采样(f28)，实测组合用例长度精确、corr=1.0、99.4% 采样相同）：f28=2^(pct/120)，先 PSOLA 变速（r=f20/f28）再走引擎同款 **12 抽头 int16 定点多相重采样器**（b0264，50 相位系数表 + afb08 flush 截断语义）；对引擎进程内 24kHz PCM 实测 pitch=+25%/+50%/-50% **逐采样 maxdiff=0**，SDK 端到端长度完全相同、99.4%~99.5% 采样相同、残差 ≤2 LSB（自然音频 ±1 LSB 固有差异）；`break` 已完全实测并复刻：句中 break 在 token 序列里被替换为 **`br3` 暂停 token**（该句音频总长 = encoder 帧数×300，与引擎逐采样同源），静音长度 = ms×24 精确；句首/句间 break 为纯插入（位置 1200 / 前句音频+1200，与引擎逐采样一致），句尾 break 忽略；9 个实测用例长度全部精确，7 个插入位置与引擎逐采样一致（个别句中 break 差 ≤900 采样，属引擎流式块调度差异）；（组合特性实测：pitch+volume 长度 26773 精确、eq 99.63%、corr=1.0；pitch+break 长度 40502 精确、eq 98.1%、corr=1.0）；Node SDK 暂未提供 SSML |
| **词边界事件** | Python SDK `word_events` 已复刻英文（19/19 逐字段一致）；中文事件与 Node 事件接口待后续版本 |
| **中文混合 token**（如 `5G`、`MP3`、`iPhone15`） | 引擎使用中文混合语（mixlingual）专用读音；当前 SDK 对中英混合 token 的读音与引擎存在差异，相关资源解析仍在进行 |
| **英式/印式英语变体** | 已支持：用引擎实测采集了 en-GB / en-IN 专用发音词表（各 4.85 万词条，含 51 个缩写读法），en-GB 的 `hello→h ax - l ow1`、en-IN 的 `world→vw ah r l dr` 等口音读法、功能词读法（`the→[d,ah]`、`to→[tr,uw]` 等）以及 en-IN 的标点约定（逗号→br3、句末无 punc、Prabhat 无结构符）均已复刻；抽样 20 句实测：en-GB 10/10、en-IN 10/10 逐采样一致（Prabhat 长句因解码分块调度约 0.995） |
| **12 个音色包的语速调整** | 语音包 INI 中 `RateAdjustment≠100` 的 12 个音色引擎会对音频做整体保音高时长伸缩（时长 ≈ 模型时长×100/RateAdjustment，音高不变）。**引擎算法已完全逆向并复刻**：`FUN_1800b0514` 基音同步处理 + `FUN_1800afcd8` SAD 基音检测 + `FUN_1800afea0` 线性交叠 + `FUN_1800b0784` 分块调度，见 SDK 分支 `openshenzhou/rateadjust.py`；同时复刻了引擎自然音频首尾各 300 采样静音（Vocoder 前导/收尾帧）。**12 个 rate≠100 音色实测：输出长度与引擎完全相同、corr=1.000000**（rate 90/95/110/150 均已验证） |

## 仓库结构（本分支：研究成果与工具）

本分支 `main` 只放**研究数据与构建/评测脚本**，不含 SDK 源码（SDK 在 `python` / `node` 分支）：

```
data/    标定数据与离线评测数据：8 语种词表/符号表/断词模型/CRF 映射/英文实测词表、
         引擎后处理分词复合词表（108,577 条）与真值 CWordBreaker 词序列、
         eval/ 下的评测语料（中文 599、中文大规模 3000、英文 5 套、八语种 golden）
tools/   数据构建、评测、验证脚本（含一键验证 verify_all.py）
```

## 数据从哪来

本项目所有数据都来自**公开来源或本机自带资源**：

- **被复现的引擎**：微软公开分发的 Azure 嵌入式语音 SDK（NuGet 包 `Microsoft.CognitiveServices.Speech.Extension.Embedded.TTS`），仅用于"对答案"，SDK 运行时不依赖它；
- **语音包（模型/词典）**：Windows 系统自带「讲述人自然语音」的 MSIX/appx 包，由使用者自行解包，本仓库不分发；
- **中文评测语料**：Windows 系统本地化界面文案（约 15 万句；599 句评测集从中留出，训练从未使用）；
- **中文小说语料**：Project Gutenberg 中文公版书（《红楼梦》等）；
- **英文语料**：Project Gutenberg 英文公版书 9 本（《爱丽丝梦游仙境》《白鲸》《双城记》《傲慢与偏见》《福尔摩斯》《德古拉》《科学怪人》《世界大战》《绿野仙踪》）；
- **全部"标准答案"**：用"仅前端"探针把官方引擎当标注器逐句采集。
